## შესავალი

### მიზანი

"სალაშქრო ბილიკი" აპლიკაცია შექმნილია როგორც ყოვლისმომცველი პლატფორმა ლაშქრობის მოყვარულთათვის, რომლებიც დაინტერესებულნი არიან საქართველოს ბუნებრივი სილამაზის შესწავლით. ეს ვებ აპლიკაცია უზრუნველყოფს დეტალურ ინფორმაციას სალაშქრო ბილიკების, ორგანიზებული ღონისძიებებისა და უსაფრთხო და სასიამოვნო ლაშქრობისთვის საჭირო აღჭურვილობის შესახებ. პლატფორმის მიზანია საქართველოში ტურიზმის ხელშეწყობა მისი მრავალფეროვანი ლანდშაფტების წარმოჩენით და სხვადასხვა დონის მოლაშქრეებისთვის აუცილებელი ინსტრუმენტების მიწოდებით.

აპლიკაცია წარმოადგენს ინოვაციურ გადაწყვეტილებას, რომელიც აერთიანებს თანამედროვე ტექნოლოგიებსა და ეკოტურიზმის პრინციპებს. იგი შექმნილია იმისთვის, რომ გააუმჯობესოს მომხმარებლების დაკავშირება საქართველოს უნიკალურ ბუნებასთან, კულტურასა და ადგილობრივ თემებთან, ამასთან უზრუნველყოს უსაფრთხო და ინფორმირებული სალაშქრო გამოცდილება.

### პროექტის მიმოხილვა

ეს React-ზე დაფუძნებული ვებ აპლიკაცია შემუშავდა როგორც სამაგისტრო ნაშრომი, თანამედროვე ვებ-დეველოპმენტის ტექნოლოგიებში, რესპონსიულ დიზაინსა და მრავალენოვან მხარდაჭერაში პროფესიონალიზმის დემონსტრირების მიზნით. აპლიკაცია ფოკუსირებულია მომხმარებლისთვის მოსახერხებელი ინტერფეისის მიწოდებაზე, რომელიც საშუალებას აძლევს მომხმარებლებს აღმოაჩინონ სალაშქრო ბილიკები, შეუერთდნენ ორგანიზებულ ლაშქრობებს და იპოვონ შესაფერისი აღჭურვილობა მათი თავგადასავლებისთვის.

პროექტი ხაზს უსვამს საქართველოს კულტურულ და ბუნებრივ მემკვიდრეობას, ხდის მას ხელმისაწვდომს როგორც ადგილობრივი, ისე საერთაშორისო ვიზიტორებისთვის ორენოვანი ინტერფეისის (ქართული და ინგლისური) საშუალებით. ბილიკების, ღონისძიებებისა და აღჭურვილობის შესახებ დეტალური ინფორმაცია განკუთვნილია ლაშქრობის გამოცდილების გასაუმჯობესებლად და პასუხისმგებლიანი ბუნებაში დასვენების ხელშეწყობისთვის.

პროექტი ასევე მიზნად ისახავს საქართველოს როგორც აქტიური ტურიზმის დანიშნულების ადგილის პოპულარიზაციას საერთაშორისო ასპარეზზე, ადგილობრივი ეკონომიკის განვითარების ხელშეწყობას და მდგრადი ტურიზმის პრაქტიკის წახალისებას, რომელიც პატივს სცემს და იცავს გარემოს.

### სამიზნე აუდიტორია

- ლაშქრობის მოყვარულები (დამწყებიდან პროფესიონალამდე)
- საქართველოს სტუმრები და ტურისტები
- ადგილობრივი მოსახლეობა, რომელიც საკუთარ გარემოს იკვლევს
- საგარეო აქტივობების ორგანიზატორები
- აღჭურვილობის მაღაზიები და მწარმოებლები
- კონსერვაციისა და ტურიზმის ორგანიზაციები
- სასწავლო დაწესებულებები და გარემოსდაცვითი განათლების პროგრამები
- ადგილობრივი ბიზნესები სალაშქრო ბილიკების მიმდებარე რეგიონებში
- ეკო და სათავგადასავლო ტურიზმით დაინტერესებული პირები
- კულტურული მემკვიდრეობისა და ისტორიის მოყვარული მოგზაურები

## ტექნიკური არქიტექტურა

### ტექნოლოგიური სტეკი

"სალაშქრო ბილიკი" აპლიკაცია აგებულია თანამედროვე ვებ დეველოპმენტის სტეკის გამოყენებით:

- **Frontend Framework**: React 19.0.0 - წარმოადგენს საფუძველს მომხმარებლის ინტერფეისის შესაქმნელად, რაც უზრუნველყოფს სწრაფ რენდერინგსა და ეფექტურ კომპონენტების მართვას. React-ის უახლესი ვერსია საშუალებას გვაძლევს გამოვიყენოთ თანამედროვე ფუნქციები, როგორიცაა დაკავებული რეჟიმი და სერვერ კომპონენტები, მომხმარებლის გამოცდილების მნიშვნელოვნად გასაუმჯობესებლად.

- **პროგრამირების ენა**: TypeScript - უზრუნველყოფს ტიპების უსაფრთხოებას და აუმჯობესებს დეველოპერის გამოცდილებას. TypeScript-ის მკაცრი ტიპიზაცია ამცირებს ბაგებს და აუმჯობესებს კოდის ხარისხსა და მოვლას. ინტერფეისების, ტიპების და ენუმერაციების ძლიერი სისტემა საშუალებას გვაძლევს შევქმნათ მკაფიოდ განსაზღვრული ხელშეკრულებები პროგრამის სხვადასხვა კომპონენტებს შორის.

- **Build Tool**: Vite 6.2.0 - უზრუნველყოფს სწრაფ დეველოპმენტსა და ოპტიმიზირებულ პროდაქშენ ბილდებს. Vite გვთავაზობს მყისიერ Hot Module Replacement (HMR) ფუნქციას, რომელიც მნიშვნელოვნად ამცირებს დეველოპმენტის დროს, რაც განსაკუთრებით მნიშვნელოვანია რთული ინტერფეისების მქონე აპლიკაციისთვის, როგორიცაა ჩვენი პროექტი.

- **სტილიზაცია**: TailwindCSS 4.1.3 - ხელს უწყობს რესპონსიული დიზაინის შექმნას utility-first მიდგომით. Tailwind CSS-ის კომპონენტების აგების ფილოსოფია იდეალურად შეესაბამება React-ის კომპონენტურ მიდგომას, რაც ხელს უწყობს სწრაფად შეიქმნას თანმიმდევრული და მოდიფიცირებადი ინტერფეისები. ჩვენი აპლიკაცია იყენებს Tailwind-ის უახლეს ვერსიას JIT (Just-In-Time) კომპილაციით, რაც ოპტიმიზირებულ CSS-ს უზრუნველყოფს.

- **მარშრუტიზაცია**: React Router Dom 7.5.0 - მართავს ნავიგაციას სხვადასხვა გვერდებს შორის, უზრუნველყოფს კლიენტის მხარეს მარშრუტიზაციას სწრაფი გადასვლებითა და პარამეტრიზებული მარშრუტების მხარდაჭერით, რაც აუცილებელია დინამიური შინაარსის მქონე აპლიკაციისთვის.

- **ინტერნაციონალიზაცია**: i18next 24.2.3 with react-i18next 15.4.1 - მხარს უჭერს მრავალენოვან კონტენტს, უზრუნველყოფს მოქნილ და ეფექტურ გზას მრავალენოვანი ინტერფეისის შესაქმნელად. i18next ეკოსისტემა საშუალებას გვაძლევს ვმართოთ თარგმანები სხვადასხვა დომენში და უზრუნველვყოთ ენის ავტომატური აღმოჩენა და მომხმარებლის პრეფერენციების დამახსოვრება.

- **რუკები**: Leaflet 1.9.4 with React-Leaflet 5.0.0-rc.2 - უზრუნველყოფს ინტერაქტიული რუკების ფუნქციონალს, საშუალებას აძლევს მომხმარებლებს ვიზუალურად გაეცნონ სალაშქრო ბილიკებს, დაათვალიერონ მარშრუტები და აღმოაჩინონ მნიშვნელოვანი წერტილები. Leaflet-ის მსუბუქი არქიტექტურა იდეალურია მობილური მოწყობილობებისთვის, რომლებიც შეზღუდული რესურსებით მუშაობენ.

- **UI კომპონენტები**: Radix UI პრიმიტივებზე აგებული მორგებული კომპონენტები მისაწვდომობისა და კასტომიზაციისთვის. ჩვენი გუნდის მიერ შექმნილი კომპონენტების ბიბლიოთეკა აერთიანებს Radix UI-ის მისაწვდომობას TailwindCSS-ის მოქნილობასთან, შედეგად ვიღებთ მოხმარებისთვის მოსახერხებელ, მისაწვდომ და ვიზუალურად მიმზიდველ ინტერფეისს.

აპლიკაცია იყენებს Radix UI პრიმიტივებზე და TailwindCSS-ზე აგებულ დიზაინის სისტემას:

- **ბარათი (Card)**: გამოიყენება მთელ აპლიკაციაში ბილიკების, ღონისძიებების და აღჭურვილობის თანმიმდევრული ფორმატით წარმოსადგენად. ბარათები შეიცავს გამოსახულებას, სათაურს, მოკლე აღწერას და დამატებით ინფორმაციას, როგორიცაა სირთულის დონე, მანძილი ან ღირებულება. კომპონენტი მხარს უჭერს სხვადასხვა განლაგებებს, როგორიცაა ჰორიზონტალური, ვერტიკალური და კომპაქტური ვარიანტები, და რესპონსიულად ადაპტირდება სხვადასხვა ეკრანის ზომებზე.

- **ნიშანი (Badge)**: აჩვენებს სტატუსის ინფორმაციას, როგორიცაა სირთულის დონე, ხელმისაწვდომობა ან ღონისძიების სტატუსი. ნიშნები აერთიანებს ფერს, ხატულებს და ტექსტს ინფორმაციის სწრაფად აღსაქმელად. კომპონენტი შეიძლება იყოს სხვადასხვა ზომის და სტილის, გამოყენების კონტექსტის მიხედვით.

- **დიალოგი (Dialog)**: მოდალური ფანჯრები დამატებითი ინფორმაციის ან დადასტურების მოთხოვნების გამოსატანად. დიალოგები შეიცავს სათაურს, შინაარსის სექციას და ქმედების ღილაკების ჯგუფს. ისინი ხელმისაწვდომია კლავიატურის კოდის მიხედვით, მხარს უჭერენ ფოკუსის ჩაკეტვას და შეიძლება დაიხუროს Escape ღილაკით, ან მოდალის გარეთ დაკლიკებით.

- **ჩანართები (Tabs)**: აწყობს შინაარსს ჩანართებიან ინტერფეისებში ინფორმაციის უკეთესი არქიტექტურისთვის. ჩანართები გამოიყენება დაკავშირებული ინფორმაციის დასაჯგუფებლად, როგორიცაა ბილიკის დეტალები, შეფასებები და რუკები, რაც მომხმარებლებს საშუალებას აძლევს იოლად გადაერთონ დაკავშირებულ კონტენტს შორის. კომპონენტი მხარს უჭერს ჰორიზონტალურ და ვერტიკალურ ორიენტაციებს, ასევე კლავიატურით ნავიგაციას.

- **არჩევა (Select)**: ჩამოსაშლელი მენიუები ფილტრებისთვის და სხვა არჩევანზე დაფუძნებული ინტერაქციებისთვის. Select კომპონენტი მორგებულია პლატფორმის დიზაინის სისტემაზე, მხარს უჭერს ჯგუფებს, დამხმარე ტექსტებს და დეაქტივირებულ ვარიანტებს. ის სრულად მიწვდენადია კლავიატურის გამოყენებით და მხარს უჭერს როგორც ერთი, ისე მრავალ არჩევანს.

- **ავატარი (Avatar)**: აჩვენებს მომხმარებლის და ორგანიზატორის პროფილის სურათებს. ავატარები ხელს უწყობს პერსონალიზაციას და გამოსახულებისთვის გამოიყენებენ ავტომატურ ცვლილებას ნაგულისხმევი ხატულისთვის, როდესაც სურათი არ არის ხელმისაწვდომი. კომპონენტი მხარს უჭერს სხვადასხვა ზომებს და სტილებს, მათ შორის წრიულ და მომრგვალებულ მართკუთხედიან ვარიანტებს.

- **აკორდეონი (Accordion)**: გამოიყენება გრძელი ინფორმაციის ჩასაკეცად კომპაქტურ, გაფართოებად და შემცირებად სექციებში. აკორდეონები გამოიყენება UX-ის გასაუმჯობესებლად, განსაკუთრებით ხშირად დასმული კითხვების, გრძელი აღწერილობების და დეტალური ინფორმაციის შემცველი სექციებისთვის.

- **შეტყობინება (Toast)**: ხანმოკლე შეტყობინებები, რომლებიც ჩნდება ქმედებების დასადასტურებლად, შეცდომების შესახებ ინფორმაციის მისაწვდად და მნიშვნელოვანი განახლებების შესატყობინებლად. ტოსტ-შეტყობინებები ავტომატურად ქრება განსაზღვრული დროის შემდეგ და შეიძლება შეიცავდეს ქმედების ღილაკებს დამატებითი ინტერაქციისთვის. მათ აქვთ სხვადასხვა ტიპი (წარმატება, შეტყობინება, გაფრთხილება, შეცდომა) ვიზუალური განსხვავების უზრუნველსაყოფად.

- **ტიპი (Tooltip)**: კონტექსტურად აჩვენებს დამატებით ინფორმაციას ან მინიშნებებს ელემენტზე გადატარებისას. ტიპები უზრუნველყოფს კონტექსტურ განმარტებებს ღილაკებზე, ხატულებზე და სხვა ინტერაქტიულ ელემენტებზე, რაც აუმჯობესებს მომხმარებლის გამოცდილებას არინტრუზიული გზით.

ყველა ეს კომპონენტი შექმნილია მისაწვდომობის, თანმიმდევრულობის და მასშტაბურობის გათვალისწინებით, რაც უზრუნველყოფს უნიფიცირებულ გამოცდილებას მთელ აპლიკაციაში.

## მონაცემთა მართვა

### მონაცემთა წყაროები

ამჟამად, აპლიკაცია იყენებს სტატიკურ მონაცემებს, რომლებიც განსაზღვრულია TypeScript ფაილებში:

- **trails.data.ts**: შეიცავს დეტალურ ინფორმაციას სალაშქრო ბილიკების შესახებ. ეს მონაცემთა ფაილი აწყობილია სტრუქტურირებული სქემით, რომელიც ინახავს ყველა საჭირო ატრიბუტს თითოეული ბილიკისთვის, მათ შორის მდებარეობას, სირთულეს, სიგრძეს, სიმაღლეს, GPS კოორდინატებს, მოკლე და ვრცელ აღწერებს, განსაკუთრებულ ფუნქციებს და სეზონური ინფორმაციას. მონაცემები შენახულია როგორც JSON-თან თავსებადი ობიექტების მასივი TypeScript ტიპის უსაფრთხოებით.

- **events.data.ts**: შეიცავს ინფორმაციას ორგანიზებული სალაშქრო ღონისძიებების შესახებ. ეს ფაილი ახდენს სტრუქტურირებას ღონისძიებების მონაცემებისა, მოიცავს თარიღებს, სტატუსებს, შეზღუდვებს, ორგანიზატორის ინფორმაციას, ფასებს და დეტალურ აღწერებს. ყოველ ღონისძიებას აქვს უნიკალური იდენტიფიკატორი და დაკავშირებულია კონკრეტულ ბილიკთან ან ბილიკებთან.

- **equipments.data.ts**: შეიცავს მონაცემებს სალაშქრო აღჭურვილობის შესახებ. ეს ფაილი ორგანიზებას უკეთებს აღჭურვილობის ინვენტარს სხვადასხვა კატეგორიებში, მათ შორის ტექნიკურ სპეციფიკაციებს, ფასებს, ხელმისაწვდომობას, ბრენდის ინფორმაციას, სეზონურ გამოყენებას და მომხმარებლის შეფასებებს. მონაცემები სტრუქტურირებულია კატეგორიების მიხედვით და მოიცავს ფილტრაციისთვის საჭირო მეტა-ინფორმაციას.

ამ სტრუქტურით ორგანიზებული სტატიკური მონაცემები საშუალებას აძლევს აპლიკაციას წარმოადგინოს რეალისტური შემთხვევა, რაც იდეალურია პროტოტიპირებისა და დემონსტრაციისთვის. თუმცა, პროდაქშენ გარემოში, ეს სტატიკური ფაილები შეიცვლება API მოთხოვნებით backend სერვერზე.

მომავალში, როდესაც აპლიკაცია გადავა სრულ-ფუნქციონირებად პროდუქციის ვერსიაზე, ეს მონაცემები იქნება შენახული მონაცემთა ბაზაში (სავარაუდოდ, MongoDB ან PostgreSQL) და ხელმისაწვდომი გახდება RESTful ან GraphQL API-ის საშუალებით. სერვერის მხარის იმპლემენტაცია უზრუნველყოფს მონაცემთა დაცვას, ავთენტიფიკაციას, ავტორიზაციას და მონაცემთა ვალიდაციას, რასაც მოითხოვს ფუნქციონირებადი პლატფორმა.

### მდგომარეობის მართვა

აპლიკაცია იყენებს React-ის ჩაშენებულ მდგომარეობის მართვის გადაწყვეტილებებს:

- **useState**: მართავს კომპონენტის დონის მდგომარეობას. ეს ჰუკი გამოიყენება ლოკალური მდგომარეობის მართვისთვის ინდივიდუალურ კომპონენტებში, როგორიცაა ფორმის შეტანები, ფილტრები, ჩართვა/გამორთვის ღილაკები და გაშლადი მენიუები. კომპონენტში მდგომარეობის იზოლირება ხელს უწყობს კომპონენტის გამოყენებადობას და ტესტირებადობას.

- **useEffect**: მართავს გვერდითა ეფექტებს, როგორიცაა მონაცემების გამოთხოვა და DOM მანიპულაციები. ეს ჰუკი გამოიყენება აპლიკაციაში მრავალი მიზნით, მათ შორის მონაცემების გამოთხოვისთვის, ენის შეცვლაზე რეაგირებისთვის, ბრაუზერის LocalStorage-თან ურთიერთქმედებისთვის და მომხმარებლის ქმედებებზე დაკვირვებისთვის. useEffect-ის დამოკიდებულების მასივი საგულდაგულოდ იმართება, რათა თავიდან იქნას აცილებული ზედმეტი რენდერი.

- **React Context**: მართავს გლობალურ მდგომარეობას ენის პრეფერენციებისთვის. LanguageContext გამოიყენება მთელ აპლიკაციაში მიმდინარე ენის მდგომარეობის შესანახად და უზრუნველსაყოფად, რომ ყველა კომპონენტს შეეძლოს წვდომა და რეაგირება ენის ცვლილებებზე. ეს განსაკუთრებით მნიშვნელოვანია მრავალენოვანი ინტერფეისის მქონე აპლიკაციისთვის.

- **useReducer**: გამოიყენება უფრო კომპლექსური მდგომარეობის ლოგიკის დასამუშავებლად, როგორიცაა ფილტრების მდგომარეობა, რომელიც მოიცავს მრავალ ურთიერთდაკავშირებულ ველს. ეს ჰუკი უზრუნველყოფს უფრო სტრუქტურირებულ მიდგომას რთული მდგომარეობის ცვლილებების სამართავად და აადვილებს მდგომარეობის ცვლილების ლოგიკის დებაგს.

- **useCallback** და **useMemo**: გამოიყენება წარმადობის ოპტიმიზაციისთვის, მძიმე გამოთვლების მემოიზაციისა და ფუნქციების ხელახალი შექმნის თავიდან აცილებისთვის. ეს ჰუკები გამოიყენება კრიტიკული კომპონენტებისთვის, როგორიცაა რუკების ვიზუალიზაცია და ფილტრაციის ფუნქციები, რათა თავიდან იქნას აცილებული არასაჭირო რერენდერები.

- **Custom Hooks**: რამდენიმე მორგებული ჰუკი შექმნილია ხშირად გამოყენებადი ლოგიკის აბსტრაჰირებისთვის, მათ შორის:

  - **useLocalStorage**: ამარტივებს მდგომარეობის შენახვას და აღდგენას localStorage-დან
  - **useTranslatedData**: მართავს მონაცემების თარგმანს მიმდინარე ენის მიხედვით
  - **useOutsideClick**: აღმოაჩენს კლიკებს მითითებული ელემენტის გარეთ, გამოსადეგია ჩამოსაშლელი მენიუებისა და მოდალური ფანჯრებისთვის
  - **useMediaQuery**: აღმოაჩენს მედია მოთხოვნების შესაბამისობას რესპონსიული დიზაინისთვის

- **localStorage**: ინახავს მომხმარებლის პრეფერენციებს სესიებს შორის. localStorage გამოიყენება რამდენიმე მომხმარებლის პრეფერენციის შესანახად, მათ შორის:
  - არჩეული ენა, რაც უზრუნველყოფს თანმიმდევრულ გამოცდილებას ვიზიტებს შორის
  - ფილტრის პრეფერენციები, რომ შენარჩუნდეს მომხმარებლის ბოლო გამოყენებული ფილტრის პარამეტრები
  - ბილიკების, ღონისძიებების და აღჭურვილობის ბოლოს ნახული დეტალები, რაც აუმჯობესებს ნავიგაციის გამოცდილებას
  - თემის პრეფერენციები (მუქი/ნათელი რეჟიმი)

მომავალში, როდესაც აპლიკაცია გადავა სრულ ფუნქციონირებულ პროდუქციის ვერსიაზე და დაემატება მეტი კომპლექსური ფუნქციები, შესაძლებელია განხილულ იქნას უფრო მძლავრი მდგომარეობის მართვის ბიბლიოთეკის დანერგვა, როგორიცაა Redux Toolkit ან Zustand. ეს ბიბლიოთეკები განსაკუთრებით სასარგებლო იქნება უფრო რთული ფუნქციებისთვის, როგორიცაა მომხმარებლის ავთენტიფიკაცია, ჯავშნების მართვა და მომხმარებლის მიერ შექმნილი კონტენტი.

## ტექნიკური განხორციელების დეტალები

### მარშრუტიზაცია

აპლიკაცია იყენებს React Router v7-ს ნავიგაციისთვის:

```typescript
const AppRoutes: React.FC = () => {
    return (
        <Routes>
            <Route path="/" element={<Landing />} />

            {/* სალაშქრო ბილიკების მარშრუტები */}
            <Route path="/hiking-trails" element={<HikingTrails />} />
            <Route path="/hiking-trails/:id" element={<HikingTrailDetail />} />

            {/* ღონისძიებების მარშრუტები */}
            <Route path="/events" element={<Events />} />
            <Route path="/events/:id" element={<EventDetail />} />

            {/* აღჭურვილობის მარშრუტები */}
            <Route path="/equipment" element={<Equipment />} />
            <Route path="/equipment/:id" element={<EquipmentDetail />} />

            {/* უცნობი მარშრუტების გადამისამართება მთავარ გვერდზე */}
            <Route path="*" element={<Navigate to="/" replace />} />
        </Routes>
    );
};
```

მარშრუტიზაციის სისტემა მხარს უჭერს:

- დინამიურ მარშრუტის პარამეტრებს დეტალური გვერდებისთვის, რაც საშუალებას აძლევს კომპონენტებს მარშრუტიდან ამოიღონ პარამეტრები (როგორიცაა `id`) `useParams` ჰუკის გამოყენებით
- უცნობი მარშრუტების ავტომატურ გადამისამართებას მთავარ გვერდზე, რაც უზრუნველყოფს, რომ მომხმარებლები არასდროს მოხვდნენ ჩიხში
- კომპონენტების ზარმაც ჩატვირთვას უკეთესი წარმადობისთვის, `React.lazy()` და `<Suspense>` ელემენტების გამოყენებით მძიმე კომპონენტებისთვის

მარშრუტიზაციის სისტემა ასევე შემუშავებულია SEO-ს გასაუმჯობესებლად, TitleProvider კომპონენტის გამოყენებით, რომელიც ავტომატურად განაახლებს დოკუმენტის სათაურს მარშრუტის ცვლილებებთან ერთად. აპლიკაცია ინარჩუნებს წინა მარშრუტებს ისტორიის სტეკში, რაც საშუალებას აძლევს მომხმარებლებს გამოიყენონ ბრაუზერის "უკან" და "წინ" ღილაკები ინტუიციურად.

### ინტერნაციონალიზაცია

აპლიკაცია ახორციელებს ინტერნაციონალიზაციას i18next-ის გამოყენებით:

```typescript
import i18n from "i18next";
import { initReactI18next } from "react-i18next";
import LanguageDetector from "i18next-browser-languagedetector";

import enTranslation from "./locales/en/translation.json";
import kaTranslation from "./locales/ka/translation.json";

i18n
  .use(LanguageDetector)
  .use(initReactI18next)
  .init({
    resources: {
      en: {
        translation: enTranslation,
      },
      ka: {
        translation: kaTranslation,
      },
    },
    fallbackLng: "en",
    interpolation: {
      escapeValue: false,
    },
    detection: {
      order: ["localStorage", "navigator"],
      caches: ["localStorage"],
    },
  });
```

i18n იმპლემენტაციის ძირითადი ფუნქციები:

- **ენის დეტექცია**: ავტომატურად აღმოაჩენს მომხმარებლის პრეფერენციულ ენას ბრაუზერის პარამეტრების საფუძველზე ან აღადგენს ბოლოს გამოყენებულ ენას localStorage-დან.

- **ენის მუდმივობა**: ინახავს ენის პრეფერენციას localStorage-ში, რაც უზრუნველყოფს თანმიმდევრულ გამოცდილებას სესიებს შორის და ხელს უშლის მომხმარებელს ყოველ ვიზიტზე თავიდან აირჩიოს ენა.

- **თარგმანების მართვა**: ორგანიზებული JSON ფაილები, რომლებიც სტრუქტურირებულია იერარქიულად, აადვილებს თარგმანების დამატებას ან შეცვლას. თარგმანები დაჯგუფებულია გასაღების მიხედვით, რაც ამარტივებს ორგანიზებას და წვდომას.

- **კომპონენტების ინტეგრაცია**: ყველა კომპონენტი იყენებს `useTranslation` ჰუკს თარგმანებზე წვდომისთვის. ეს ჰუკი აბრუნებს `t` ფუნქციას, რომელიც გამოიყენება თარგმანის გასაღების შესაბამისი ტექსტის მისაღებად მიმდინარე ენაზე.

```typescript
// ჰუკის გამოყენების მაგალითი კომპონენტში
const { t } = useTranslation();
return <h1>{t('homepage.welcome')}</h1>;
```

- **თარგმანის ინტერპოლაცია**: i18next მხარს უჭერს დინამიური მნიშვნელობების ინტერპოლაციას თარგმანის სტრიქონებში, რაც საშუალებას აძლევს აპლიკაციას შექმნას კონტექსტზე დამოკიდებული სტრიქონები:

```typescript
// თარგმანის გასაღები: 'trail.distance': '{{distance}} კმ'
return <span>{t('trail.distance', { distance: trail.length })}</span>;
```

- **მრავალობითი ფორმები**: i18next მხარს უჭერს მრავლობითი ფორმების მართვას, რაც მნიშვნელოვანია ქართული ენისთვის, რომელსაც აქვს კომპლექსური მრავლობითი წესები.

- **ნამდვილ დროში ენის გადართვა**: აპლიკაცია უზრუნველყოფს ენის უწყვეტ გადართვას გვერდის ხელახალი ჩატვირთვის გარეშე. როდესაც მომხმარებელი ცვლის ენას, LanguageContext განახლდება და ეს ცვლილება მყისიერად აისახება მთელ აპლიკაციაში.

- **თარიღებისა და რიცხვების ფორმატირება**: ინტერნაციონალიზაცია სცილდება მხოლოდ ტექსტს და ასევე მოიცავს თარიღების, დროისა და რიცხვების ფორმატირებას ლოკალის შესაბამისად, date-fns ბიბლიოთეკის გამოყენებით.

### კომპონენტების სტრუქტურა

აპლიკაცია მისდევს კომპონენტებზე დაფუძნებულ არქიტექტურას:

- **გვერდის კომპონენტები**: ზედა დონის კომპონენტები, რომლებსაც რენდერი უკეთდება მარშრუტების მიერ, როგორიცაა Landing, HikingTrailsList, EventDetail. ეს კომპონენტები ასრულებენ გვერდის კონტეინერის როლს და აერთიანებენ სხვადასხვა ფუნქციონალურ კომპონენტებს თანმიმდევრული გამოცდილების შესაქმნელად.

- **ფუნქციონალური კომპონენტები**: სპეციალიზებული კომპონენტები კონკრეტული ფუნქციებისთვის (მაგალითად, TrailCard, EventDetailHeader, EquipmentFilter). ეს კომპონენტები ახდენენ კონკრეტული საქმიანი ლოგიკის ინკაფსულაციას და წარმოადგენენ განსაზღვრულ ფუნქციებს აპლიკაციაში. ისინი ასრულებენ კონკრეტულ მიზანს და შეძლებისდაგვარად არიან გამოყენებადი და მოდულარული.

- **საზიარო კომპონენტები**: მრავალჯერადი გამოყენების UI ელემენტები, რომლებიც საზიაროა მთელ აპლიკაციაში, როგორიცაა Button, Card, Badge და Modal. ეს კომპონენტები შეადგენენ დიზაინის სისტემის საფუძველს და უზრუნველყოფენ ვიზუალურ თანმიმდევრულობას მთელ აპლიკაციაში. ისინი გადასცემენ პროპებს კონფიგურაციისთვის და იყენებენ კომპოზიციას მრავალმხრივი მომხმარებლის ინტერფეისის შესაქმნელად.

- **განლაგების კომპონენტები**: აწყობენ მთლიან გვერდის განლაგებას (Header, Footer, Layout). ეს კომპონენტები უზრუნველყოფენ თანმიმდევრულ სტრუქტურას და პოზიციონირებას მთელ აპლიკაციაში, განსაზღვრავენ გრიდს, ნავიგაციას და გვერდის საერთო ორგანიზებას.

კომპონენტები შექმნილია გამოყენებადობის, მოვლის სიმარტივისა და წარმადობის ოპტიმიზაციისთვის, სადაც შესაძლებელია React.memo-ს გამოყენებით, თავიდან რომ ავიცილოთ არასაჭირო რერენდერები.

ტიპიური კომპონენტის სტრუქტურა შემდეგნაირია:

```typescript
// იმპორტები
import React, { useState, useEffect } from 'react';
import { useTranslation } from 'react-i18next';
import classNames from 'clsx';

// პროპების ტიპის განსაზღვრა
interface ButtonProps {
  variant?: 'primary' | 'secondary' | 'outline';
  size?: 'sm' | 'md' | 'lg';
  children: React.ReactNode;
  onClick?: () => void;
  disabled?: boolean;
  className?: string;
}

// კომპონენტის განსაზღვრა
export const Button: React.FC<ButtonProps> = ({
  variant = 'primary',
  size = 'md',
  children,
  onClick,
  disabled = false,
  className = '',
}) => {
  // თარგმანის ჰუკის გამოყენება
  const { t } = useTranslation();

  // CSS კლასების გამოთვლა
  const buttonClasses = classNames(
    'button',
    `button-${variant}`,
    `button-${size}`,
    { 'button-disabled': disabled },
    className
  );

  // კომპონენტის რენდერი
  return (
    <button
      className={buttonClasses}
      onClick={onClick}
      disabled={disabled}
      aria-disabled={disabled}
    >
      {children}
    </button>
  );
};

// კომპონენტის ექსპორტი
export default React.memo(Button);
```

კომპონენტები ორგანიზებულია ფოლდერებში იერარქიული სტრუქტურით, რომელიც ასახავს მათ როლსა და ურთიერთკავშირს. თითოეული კომპონენტი უზრუნველყოფს კარგად განსაზღვრულ API პროპების საშუალებით და იყენებს უნიშვნელო მდგომარეობას, როდესაც ეს შესაძლებელია.

### რესპონსიული დიზაინი

აპლიკაცია არის სრულად რესპონსიული, ეგუება სხვადასხვა ეკრანის ზომებს:

- **მობილურ-პირველი მიდგომა**: საბაზისო სტილები მიზანმიმართულია მობილური მოწყობილობებისთვის და შემდეგ ფართოვდება უფრო დიდი ეკრანებისთვის. ეს უზრუნველყოფს ოპტიმალურ გამოცდილებას მცირე ეკრანის მოწყობილობებზე, პირველ რიგში ოპტიმიზაციას უკეთებს მობილურ დიზაინს და შემდეგ ამდიდრებს გამოცდილებას უფრო დიდი ეკრანის ზომებისთვის.

- **Tailwind ბრეიქპოინტები**: იყენებს Tailwind-ის რესპონსიულ მოდიფიკატორებს (sm, md, lg, xl, 2xl) თანმიმდევრული ბრეიქპოინტებისთვის. ეს რესპონსიული სისტემა უზრუნველყოფს თანმიმდევრულ განლაგების ცვლილებებს სხვადასხვა მოწყობილობებს შორის და მოიცავს შემდეგ ბრეიქპოინტებს:
  - `sm`: >= 640px (პატარა მოწყობილობები)
  - `md`: >= 768px (პლანშეტები)
  - `lg`: >= 1024px (პატარა ლეპტოპები)
  - `xl`: >= 1280px (დესკტოპები)
  - `2xl`: >= 1536px (დიდი ეკრანები)

```jsx
<div className="flex flex-col sm:flex-row sm:items-center md:justify-between">
  {/* კონტენტი ადაპტირდება მობილურიდან დესკტოპზე */}
</div>
```

- **ადაპტაციური განლაგებები**: ერთსვეტიანიდან მრავალსვეტიან განლაგებაზე გადართვა ეკრანის ზომის საფუძველზე. პატარა ეკრანებზე ელემენტები ტიპიურად განლაგებულია ვერტიკალურად, ხოლო უფრო დიდ ეკრანებზე ჰორიზონტალურად ან გრიდ განლაგებაში გამოიყენება სივრცის ეფექტური გამოყენებისთვის.

- **ოპტიმიზებული სურათები**: სურათები შესაბამისად ზომირდება სხვადასხვა მოწყობილობებისთვის, CSS-ის object-fit თვისებებით და srcset ატრიბუტებით HTML-ის img ტეგებისთვის. აპლიკაცია იყენებს გამოსახულების ოპტიმიზაციის ტექნიკებს, როგორიცაა ლეივიზი-ლოუდინგი, პროგრესული ჩატვირთვა და შესაბამისი ფორმატები სხვადასხვა მოწყობილობებისა და ეკრანის სიმკვრივისთვის.

- **მხედველობაში მისაღები ნატიური აპლიკაციები**: ნატიური iOS და Android აპლიკაციების პოტენციური განვითარება სპეციფიური მოწყობილობის შესაძლებლობების გამოყენებისთვის (მაგ., GPS და სენსორები).
- **ჭკვიანი საათების და სატარებელი ტექნოლოგიების მხარდაჭერა**: გაფართოება მცირე ფორმატის მოწყობილობებზე ძირითადი ნავიგაციის და ინფორმაციული ფუნქციებით.
